# 회원 품목 셀프 추가

작성일 2026-08-09

## 배경

업체가 발주할 수 있는 품목을 관리자가 하나하나 등록해 줘야 한다. 그래서 회원은 자기
목록에 없는 품목을 시킬 수 없고, 결국 전화나 문자로 부탁하게 된다.

2026-08-09 실측:

| | 값 |
|---|---|
| 활성 품목 | 137개 |
| 업체별 등록된 품목 | 538건 / 39개 업체 |
| 업체당 평균 | 14개 (최소 1, 최대 37) |

회원은 평균 14개만 보고 나머지 120여 개를 못 본다.

최근 한 달(7/15~) 발주 경로:

| 경로 | 발주 건수 | 업체 수 |
|---|---|---|
| 웹 발주화면 | 201 | 27 |
| **어드민이 대신 입력** | **129** | 23 |
| 모바일 앱 | 17 | 7 |

**어드민 대신 입력이 129건**이다. 그중 일부는 "내 목록에 그 품목이 없어서" 일 가능성이
높다. 회원이 직접 추가할 수 있으면 그 부담이 준다.

## 목표

회원이 등록된 전체 품목을 보고 필요한 것을 직접 자기 발주 목록에 넣는다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 단가 표시 | 기본 단가를 그대로 보여준다. 실제 청구는 발주일 기준으로 다시 계산된다 |
| 추가 방식 | 단가 있으면 즉시(114개) / 없으면 요청 후 관리자 확인(23개) |
| 삭제 권한 | 회원이 추가한 것만 회원이 뺀다. 관리자가 넣은 기본 품목은 못 뺀다 |
| 적용 범위 | 웹 먼저. 앱은 다음 배포 |
| 요청 알림 | 어드민 화면 목록만. 별도 알림 없음 |

### 왜 단가 유무로 나누는가

단가 없는 품목이 그대로 발주되면 명세서가 0 원으로 나간다. 2026-08-09 에 실제로 있었다 —
`일회용 손장갑`이 단가 없이 발주돼 명세서에 0 원으로 잡혔다. 지금은 관리자가 품목을
등록하면서 단가도 같이 챙기지만, 회원이 직접 넣게 되면 그 단계가 없어진다.

단가 없는 23개:
```
고향냉면비빔장, 기타품목, 김치 10kg, 눈꽃치즈, 당귀, 레몬 6개 팩, 매실원액,
면사랑 냉면육수 소고기 5Kg, 모짜렐라, 목이버섯, 미향 말통, 바나나, 백목이버섯,
비닐봉투, 사과, 산초가루, 서진김치 10Kg, 세척당근, 수입생강, 스모크햄,
식용류, 참외, 통후추
```
`기타품목`처럼 애초에 회원이 발주하면 안 되는 것도 섞여 있다. 확인 단계가 그것도 막는다.

## 데이터 모델

### `restaurant_products` 에 출처를 남긴다

지금은 누가 넣었는지 알 수 없어 회원이 뺄 수 있는 것과 없는 것을 구분할 수 없다.

| 컬럼 | 타입 | 뜻 |
|---|---|---|
| `added_by` | text | `'admin'` \| `'member'`. 기본값 `'admin'` |
| `added_by_user` | uuid | 넣은 사람 |
| `added_at` | timestamptz | |

기존 538 건은 전부 관리자가 넣은 것이므로 기본값 `'admin'` 이 맞다.

### 요청 대기용 `product_requests` 를 새로 만든다

| 컬럼 | 타입 | 뜻 |
|---|---|---|
| `id` | uuid | |
| `restaurant_id` | uuid | |
| `product_id` | uuid | |
| `requested_by` | uuid | |
| `requested_at` | timestamptz | |
| `status` | text | `'pending'` \| `'approved'` \| `'rejected'` |
| `decided_at` | timestamptz | |
| `decided_by` | uuid | |

`(restaurant_id, product_id)` 에 부분 unique 를 걸어 같은 품목을 여러 번 요청하지 못하게
한다 (`status = 'pending'` 일 때만).

**`restaurant_products` 에 status 를 두지 않고 표를 따로 빼는 이유**: 발주 화면이
`restaurant_products` 를 그대로 읽는다(`app/member/order/page.tsx`). 대기 상태를 같은 표에
섞으면 아직 안 열린 품목이 발주 목록에 새어 나갈 수 있다. 한 줄만 빼먹어도 그렇게 된다.

## 회원 화면

`app/member/order` 발주 화면 하단에 「품목 추가」를 둔다. 화면은 이미 분류별로 품목을
묶어 보여주므로 같은 방식으로 그린다.

```
품목 추가                                    [닫기]

채소 🥬
  ☐ 깻잎        27,000원/box
  ☐ 시금치       3,000원/ea
  ☐ 사과                        단가 문의

선택한 3개 추가
```

- 이미 내 목록에 있는 품목은 안 보인다
- 단가 있으면 금액, 없으면 「단가 문의」
- 단가 없는 것을 고르면 바로 안 열리고 요청으로 들어간다. 회원 화면에 「확인 중」으로 남는다
- 한 번에 여러 개를 고를 수 있다

내 목록에서는 **`added_by = 'member'` 인 품목에만 `×`** 가 붙는다.

## 어드민 화면

품목 관리에 「품목 요청」을 둔다.

```
품목 요청 3건

월미당      사과        요청 08-10    [단가 등록 후 승인] [거절]
돈마나      모짜렐라     요청 08-10    [단가 등록 후 승인] [거절]
```

**승인은 단가가 있어야 된다.** 단가 없이 승인하면 0 원 명세서가 나온다. 승인 버튼은
단가가 없으면 단가 등록 화면으로 먼저 보낸다.

승인하면 `restaurant_products` 에 `added_by = 'member'` 로 넣는다 — 회원이 원해서 열린
품목이므로 회원이 뺄 수 있어야 한다.

## 안전장치 — 단가 0 원 발주 경고

회원이 품목을 직접 넣게 되면 0 원 발주 위험이 커진다. 발주를 저장할 때 단가가 0 인
품목이 있으면 회원 화면에 경고를 띄운다.

```
⚠ 단가가 정해지지 않은 품목이 있습니다 — 사과
   그대로 발주하면 금액이 0 원으로 잡힙니다. 담당자에게 확인해 주세요.
```

막지는 않는다. 급해서 일단 시켜야 하는 경우가 있고, 관리자가 명세서에서 고칠 수 있다.
2026-08-09 에 실제로 겪은 문제라 이번에 같이 넣는다.

## 하지 않는 것

- **모바일 앱** — 다음 배포에. 최근 한 달 앱 발주가 17건(7개 업체)뿐이라 웹이 먼저다
- **요청 알림(문자·푸시)** — 화면 목록만
- **품목 검색** — 137개라 분류별 목록으로 충분하다. 더 늘면 그때 넣는다
- **회원이 새 품목을 만드는 것** — 품목 마스터 등록은 관리자만 한다

## 검증

1. 회원이 단가 있는 품목을 추가한다 → 즉시 발주 목록에 뜨는가
2. 회원이 단가 없는 품목을 고른다 → 요청으로 들어가고 발주 목록에는 안 뜨는가
3. 관리자가 요청을 승인한다 → 회원 목록에 뜨고 `added_by='member'` 인가
4. 회원이 자기가 추가한 품목을 뺀다 → 목록에서 사라지는가
5. 회원이 관리자가 넣은 기본 품목을 빼려 한다 → `×` 가 없는가
6. 단가 0 인 품목을 발주한다 → 경고가 뜨는가
7. 같은 품목을 두 번 요청한다 → 막히는가
8. 다른 업체 품목 목록이 새지 않는가

검증은 **테스트 식당(`7306bb64-4596-4a5e-92ab-6e9dd9395238`)으로만** 한다.
실거래 업체의 `restaurant_products` 를 건드리지 않는다.

## 열린 문제

- **어드민 대신 입력 129건의 실제 이유** — "목록에 없어서"인지 다른 이유인지 확인 안 됐다.
  이 기능을 낸 뒤 그 수치가 줄어드는지 보면 알 수 있다.
- **단가 없는 23개 중 상당수가 안 쓰는 품목으로 보인다.** 정리하면 요청 자체가 거의 안
  생길 수 있다. 별도 건.
