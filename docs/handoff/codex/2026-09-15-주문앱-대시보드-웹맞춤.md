# 주문앱 대시보드 모바일 웹 맞춤

상태: 진행중 — 로컬 구현·자동 검사 완료, API 배포 및 실기기 비교 대기

## 기준과 확인된 차이

사용자가 첨부한 9/15 모바일 웹 스크린샷과 `apps/web/app/member/dashboard/page.tsx`, `SupplyRiskSection.tsx`를 비교했다. 로그인한 운영 웹을 직접 열어 비교한 것은 아니다.

- 기존 앱에 전일 금액, 월 납품 합계/최근 납품일, 2주 차트, 수급 반입량 비교, 문의 목록이 없었다.
- 앱은 변동 단가 품목만 필터링하고 클릭해야 세부 분석을 보여줬다. 웹은 최근 납품에서 금액이 가장 큰 품목을 선정하고 분석을 펼쳐 표시한다.
- 앱의 직접 DB 조회와 기존 dashboard-analysis API의 주간 집계도 웹과 달랐다.

## 이번 변경

- 고객앱 `apps/mobile/app/(tabs)/index.tsx`를 웹 카드 순서/색/테두리/분석 기준으로 변경. 현재 단가 접기 기능은 유지하되 기본 펼침. 네이티브 상·하단 내비게이션과 안전영역은 유지한다(브라우저 툴바는 복제하지 않음).
- `dashboard-analysis`에 하위 호환 `webDashboard` 추가. 기존 응답 필드 유지. 인증된 회원의 업체로 조회 범위를 제한하고 no-store 설정.
- `lib/member-dashboard.ts`에서 대표 품목, 14일 날짜별 가격, 수량/비용/평균 집계. 수급 분석은 웹과 같은 `getSupplyTrend` 및 `toMarketName` 사용.
- 집계 데이터 조회 실패는 0원/빈 결과로 숨기지 않는다. 수급 분석 실패는 별도 오류로 표시.
- 대시보드 복귀·앱 활성화·60초 간격 갱신, 이전 요청 응답 무시, 조회 시간제한 추가. 공지 갱신 훅 유지.
- 최근 납품일을 누르면 정산의 해당 날짜 명세서를 펼친다. 문의 작성/상세, 정산 이동 연결.
- 웹의 하단 '최근 7일' 표기는 실제 조회가 14일이라 앱에서는 '최근 2주'로 표기. 웹 자체는 수정하지 않았다. 0수량을 임의로 1로 표시하지 않는다.

## 검증

- 모바일 tsc, 웹 tsc 통과.
- 웹 전체 테스트 97개 통과. 새 테스트 8개: 대표 품목, 14일 가격 이월, 품목 비용, 일정 단가 표시, 빈 자료, 인증/업체 범위, 조회 오류.
- Android/iOS Expo export 성공: `/tmp/fruitlife-dashboard-parity` (스토어 빌드 아님).
- git diff --check 통과. 실제 주문/결제/배송 데이터 변경 없음.

## 남은 작업 / 중요

- 운영 API에는 새 webDashboard 필드가 없으므로 현재 운영 API를 쓰는 Expo Go에서는 '서버 API가 아직 배포되지 않았습니다' 안내가 표시될 수 있다. **현 상태에서 Expo 화면 확인 완료라고 안내하지 말 것.**
- 승인된 로컬 테스트 서버 또는 API 배포 후 실제 기기에서 금액/품목/차트/각 링크를 확인해야 한다. 현재 실기기 시각 검증은 미완료.
- 커밋/푸시/배포/스토어 빌드 하지 않았다. 배포는 사용자 승인 후 GitHub push → Cloudflare 자동배포만.
- 별도 배송앱 변경 및 다른 미커밋 수정은 보존한다.
- 앞서 신고된 '내일 발주 등록 불가'는 정확한 화면/오류를 받지 못해 원인 미확정이며 이 대시보드 변경으로 해결됐다고 주장하지 않는다.
