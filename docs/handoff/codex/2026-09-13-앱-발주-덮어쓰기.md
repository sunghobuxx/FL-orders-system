# 앱에서 품목을 추가하면 기존 발주가 지워진다

**상태: 대기** · 작성 2026-09-13 · 웹은 고쳐서 배포함, **앱만 남음**

## 한 줄

발주를 제출한 뒤 품목을 추가해 다시 제출하면, **앞서 넣은 품목이 전부 사라지고 방금 넣은 것만 남는다.**
실제로 오발주가 났다. 웹은 막았고, **모바일 앱은 아직 뚫려 있다.**

## 실제 사고

할매솥뚜껑삼겹살 일산킨텍스점, 2026-09-12 납품분.

| 시각(KST) | 일 |
|---|---|
| 9/11 22:46:30 | 발주 제출 (여러 품목) |
| 9/11 22:47:06 | 36초 뒤 재제출 — **꽃상추 1박스만** |
| 결과 | 앞 품목 전부 삭제. 명세서·발주 문자까지 꽃상추만 나감 |

빠진 품목(일자 2box·미나리 1box·깻잎 1box·깐마늘 2kg)은 9/13 자로 따로 보충했다.

## 원인

`apps/web/app/api/member/orders/route.ts` 는 제출을 받을 때마다
**그 발주의 `order_items` 를 전부 지우고 받은 것만 다시 넣는다.**

```
order_items 전부 delete → 받은 items insert
```

추가가 아니라 **교체**다. 그래서 화면에 기존 품목이 안 실린 채로 제출되면
안 보낸 품목이 통째로 사라진다.

## 웹은 이렇게 막았다 (참고용, 이미 배포됨)

**1. 서버 가드** — `lib/orders/stale-submit.ts` 의 `isStaleOrderSubmit()`

요청이 `orderId` 를 **명시**했는데 서버의 최신 발주와 다르면(없다고 했는데 있거나, 다른 발주를
가리키면) 그 화면은 낡은 것이다. 409 로 돌려보낸다 — 지우지 않는다.

```
이미 접수된 발주가 있습니다. 화면을 새로고침한 뒤 다시 시도해 주세요.
```

**`orderId` 키 자체가 없으면 막지 않는다.** 지금 앱이 그렇다 — 판단 근거가 없어서 통과시킨다.
그래서 **앱은 아직 보호되지 않는다.**

**2. 화면** — `app/member/order/OrderForm.tsx` 가 뜰 때 `router.refresh()`,
뒤로 가기로 되살아난 화면(`pageshow` + `persisted`)은 통째로 다시 읽는다.

## 앱에서 할 일

`apps/mobile/app/(tabs)/order.tsx` 의 `submitOrder`

**1) 제출할 때 `orderId` 를 같이 보낸다.** 이것만 하면 앱도 서버 가드가 걸린다.

```ts
body: JSON.stringify({
  restaurantId,
  businessDate,
  batchId: todayBatch?.id ?? null,
  orderId: currentOrderId ?? null,   // ← 추가. 불러온 발주의 id, 없으면 null
  items,
  isSubmit: true,
})
```

`currentOrderId` 는 `loadCurrent` 에서 발주를 읽을 때 같이 담아 두면 된다
(지금은 `order.id` 로 `order_items` 만 읽고 버린다).

**2) 409 를 사람이 읽는 말로 보여준다.** 서버 메시지를 그대로 띄우고, 목록을 다시 불러온다.

**3) 발주 탭으로 돌아올 때 항상 다시 읽는다.** 제출 후 상태 탭으로 갔다가 발주 탭으로
돌아오면 화면이 옛 상태일 수 있다. `useFocusEffect` 로 `reload(restaurantId)` 를 부르면 된다.

## 검증

1. 앱에서 품목 2개 발주 제출
2. 발주 탭으로 돌아와 품목 1개 추가 → 제출
3. **3개가 다 남아 있어야 한다.** 1개만 남으면 안 고쳐진 것이다

```sql
-- 재제출로 품목이 줄었는지 보는 눈
select o.name, b.business_date, ord.order_no,
       (ord.created_at at time zone 'Asia/Seoul') as 발주생성,
       (min(oi.created_at) at time zone 'Asia/Seoul') as 품목최초기록,
       count(oi.id) as 품목수
from orders ord
join order_batches b on b.id = ord.batch_id
join restaurants r on r.id = b.restaurant_id
join organizations o on o.id = r.organization_id
join order_items oi on oi.order_id = ord.id
where b.business_date >= current_date - 7
group by 1,2,3,ord.created_at
having extract(epoch from (min(oi.created_at) - ord.created_at)) > 10
order by 2 desc;
```

발주 생성 시각과 품목 기록 시각이 크게 벌어진 건이 재제출이다. 그중 품목 수가 비정상적으로
적은 건을 보면 된다.
