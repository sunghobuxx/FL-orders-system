# 앱: 단가 확정 표시 (배송관리 앱)

- 상태: **대기**
- 요청일: 2026-09-25
- 관련: `docs/superpowers/specs/2026-09-25-당일단가-확정-표시-design.md`

## 왜
아침 배송 매니저는 **전날 명세서**를 날짜를 골라 인쇄해서 업체에 건넨다. 그 날짜의 단가가 확정인지 임시인지 모르고 뽑으면
업체가 임시 금액을 확정으로 오해한다. 앱 목록에서 확정 여부가 보이고, **인쇄된 종이에도 상태가 찍혀야 한다.**

## 서버는 이미 준비돼 있다 (앱 업데이트 전에도 앱은 지금처럼 동작한다)
`GET /api/driver/specs` (`mode=today` 와 `mode=history` 모두)의 각 명세서에 **새 필드만 추가**됐다. 기존 필드는 그대로다.

```json
{
  "specs": [
    {
      "id": "…", "businessDate": "2026-09-24", "totalAmount": 250000,
      "priceStatus": { "status": "confirmed", "at": "2026-09-24T04:10:00+00:00" }
    }
  ]
}
```

- `priceStatus.status`: `pending` | `confirmed` | `modified` | `final`. **시행일 이전 날짜는 `priceStatus` 필드 자체가 없다.**
- `pending` 은 **아무리 오래된 날짜라도 항상 내려온다**(배송앱은 숨기지 않는다 — 표시가 없으면 "확정이라 표시가 없는 것"으로 오해하기 때문).
- `final` = 그 명세서를 포함한 정산서가 확정됨(금액이 최종).
- `at`: 확정 시각(`confirmed`) / 수정 시각(`modified`)의 UTC ISO. `pending`·`final` 은 `null`. **화면·인쇄에는 KST(+9) `HH:MM`** 으로 표시한다.

## 앱에서 할 일
1. **명세서 탭 목록**(`apps/driver-mobile/app/(tabs)/specs.tsx`): 각 명세서 카드에 `priceStatus` 배지를 보여준다. **`pending`·`modified` 는 눈에 띄는 색**(노랑·주황)으로 — 매니저가 "이 날짜는 뽑지 않는다"를 한눈에 알 수 있어야 한다. `confirmed` 는 초록, `final` 은 회색 작은 글씨.
2. **인쇄물**(`createSpecHtml`): 제목 `<h2>${printDateLabel} 발주 명세표</h2>` **바로 아래**에 상태 문구 한 줄을 넣는다. `pending`·`modified`·`confirmed` 만 찍고 **`final`·없음은 찍지 않는다.** 스타일 예: `text-align:center; font-size:10pt; font-weight:bold; border:1px solid #000; padding:3px 0; margin:-3mm 0 4mm`.
3. `history` 탭 목록에도 같은 배지를 붙인다(`mode=history` 응답에 같은 필드가 있다).

## 월정산 업체 (`confirmed` 인데 `at` 이 `null`)
**월정산 업체는 시행일 이후 날짜가 전부 `confirmed` 로 내려오고, 이때 `at` 은 `null` 이다.** 시각 없이 **`✓ 당일 단가 확정`** 만 표시한다
(`(13:10)` 괄호 없음). `at` 이 있으면 지금처럼 시각을 붙인다.

## 문구 (정확히)
| status | 화면·인쇄 문구 |
|---|---|
| `pending` | 단가 입력 중 · 금액이 바뀔 수 있습니다 (이전 단가 기준) |
| `confirmed` | ✓ 당일 단가 확정 (13:10) |
| `modified` | 단가 수정됨 · 금액이 바뀔 수 있습니다 (13:40 수정) |
| `final` | 정산 확정 (목록에만, 인쇄에는 찍지 않음) |

웹 구현은 `apps/web/lib/pricing/price-status.ts`(`priceStatusText`, `priceStatusPrintText`)와
`apps/web/app/print/spec/page.tsx`(웹 인쇄 화면)를 그대로 참고하면 된다.

## 하지 않는 것
- **인쇄 전 경고창·인쇄 차단은 만들지 않는다.** 매니저가 배지를 보고 스스로 고르는 흐름이다. 차단하면 사장님이 확정을 늦게 하는 날 명세서를 못 뽑는다.
- 앱에서 확정 버튼을 만들지 않는다.

## 알아둘 점
인쇄 HTML 이 앱 안에서 만들어지므로 **앱이 업데이트되기 전에는 종이에 표시가 찍히지 않는다.** 웹 인쇄 화면은 서버 배포 즉시 적용된다.

## 확인 방법
서버 배포 후 어드민에서 단가를 「확정」하기 전/후/수정 후 앱에서 명세서 목록과 인쇄 미리보기를 확인한다. 오래된 날짜(예: 시행일 이후 미확정 날짜)에도 `pending` 배지가 보여야 한다.
