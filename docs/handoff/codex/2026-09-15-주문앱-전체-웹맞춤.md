# 주문앱 모바일 웹 동작 맞춤

상태: 진행중 — 로컬 구현/자동 검사 완료, API 배포 및 실제 기기 검증 대기

## 범위

- 고객용 `apps/mobile`. 배송관리 `apps/driver-mobile` 변경 없음.
- 사용자가 정상 사용하는 모바일 웹과 동작을 맞추도록 요청.
- 기존 미커밋 변경 유지. 커밋/푸시/배포/빌드 제출, 운영 주문·결제·문자 발송 없음.

## 이번 변경

- `/api/member/order-form`: 검증된 사용자 소속 식당만 조회. 서버 KST 시간으로 웹과 같은 기본 배송일 결정(04:00 이후 다음날). 명시적 날짜 조회. 지정 품목 없으면 활성 품목 전체. 기존 발주 품목은 지정 목록에서 빠져도 보존.
- 발주 입력: 작성 중 자동 갱신/탭 이동으로 수량이 사라지지 않음. 기존 발주 ID·날짜·수량·단위 변경 감지 후 제출 중단. 실패한 조회를 빈 주문으로 취급하지 않음. 응답 지연 25초 제한, 저장 결과 불확실 시 재조회 요구. 날짜 선택 및 내일 배송 버튼, 잠긴 발주에서 입력 탭으로 돌아오면 서버 기본 날짜 조회.
- 발주 확인/내역: 저장된 수량 표시, completed 최종 배송 단계, 명세서 연결, 최근 30일 및 금액 표시.
- `/api/member/settlement`: 웹과 같은 명세서/미수금 원천 조회, 부분 납부 잔액과 납품 합계 구분. 검증된 소속 업체 제한. 조회 실패 시 0원으로 표시하지 않음.
- 앱 정산/명세서: 단가·수량·금액, 월별 명세서 내역, 인쇄, 실제 잔액으로 웹 결제 연결. 조회 시점 미수금에 당일 금액을 중복 가산하지 않음.
- `/mobile-payment` 및 로그인 복귀 경로: 브라우저 로그인 필요 시 결제 화면으로 복귀. 토큰 URL 전달 없음. 내부 `/member/payment`만 허용. 실제 결제 화면의 권한·잔액 검증 유지.
- 프로필: 웹의 contacts/restaurant 필드 저장 경로 사용. profile GET 추가, PUT bearer 지원. 소유권 확인 후 쓰기.
- 웨이팅: 기존 웹 API를 사용하고 별도 waiting DB는 유지. 실제 QR 생성. 조회 오류와 알림 전송 실패 표시. 새 실제 SMS 발송 없음.
- 공지/문의: 기존 공지 갱신 작업 유지, 문의 조회 실패를 빈 목록과 구분.
- expo-print, qrcode-generator를 apps/mobile에 추가.
- 대시보드 선행 변경: `2026-09-15-주문앱-대시보드-웹맞춤.md` 참조.

## 검증

- web Vitest: 20개 파일, 116개 테스트 통과.
- mobile `npx tsc --noEmit`, web `pnpm exec tsc --noEmit --incremental false` 통과.
- iOS/Android JS/Hermes export 성공: `/tmp/fruitlife-member-parity-final` (스토어 설치 빌드 아님).
- 신규 테스트: order-form 인증/업체 범위/날짜/전체 품목/조회 실패, 토큰 fail-closed, 정산 부분 납부·실패 처리, 입력 보존·지문·HTML escape·결제 복귀 URL.

## 다음 작업 및 주의

- 새 API가 운영에 없으므로 지금 운영 API를 보는 Expo Go에서 최종 기능 검증 불가. 승인 후 필요한 web API와 모바일을 함께 릴리스해야 함. 앱부터 먼저 배포하지 말 것.
- 사용자 계정으로 실제 기기에서 내일 날짜 발주 조회/수정, 수량·단위·품목 추가, 명세서/프린트, 결제 로그인 복귀, QR·알림 흐름 확인 필요. 이 단계는 아직 완료하지 않음.
- 실물 프린터/Android 시스템 인쇄의 연속 호출 및 결제 전 과정 미검증. 사진 첨부와 웨이팅 문자 전송은 기존 서버 기능을 연결했으나 실전 전송하지 않음.
- 발주 preflight 비교는 원자적 DB 트랜잭션이 아님. 기존 API의 orderId 충돌 검증을 유지하며 동시 갱신 완전 보장은 별도 서버 트랜잭션 작업 필요.
- 네이티브 하단 탭/안전영역은 유지. 모바일 웹과 모든 화면의 픽셀 단위 일치 검증을 완료했다고 표현하지 말 것.
- 다른 대화의 파일 포함 `git add .`, 전체 복원 금지. 승인 전 푸시·배포 금지.
