# 배송관리앱 발주내역 — 전체 / 가락 / 기존 구성 + 날짜 선택

상태: 웹 구현 완료(가락 확인 버튼 포함). **배송관리앱(`apps/driver-mobile`)은 아직 구현 전** — 아래 구성대로 맞춰 주세요.

## 현재 차이
- 모바일 당일 발주 집계는 오늘 날짜만 보인다. 웹처럼 날짜를 골라 지난 발주를 볼 수 없다.
- 모바일은 발주내역을 한 덩어리로만 보여준다. 웹은 아래 3개 구역으로 나눈다.

## 웹 구성 (기준)
웹 화면: `apps/web/app/admin/orders/dispatch/[date]/page.tsx`

날짜는 URL에 든다 (`/admin/orders/dispatch/YYYY-MM-DD`).
- 기본 날짜: KST 18시 이전은 오늘, 18시 이후는 내일 (`app/admin/orders/dispatch/page.tsx`).
- 날짜 이동 버튼(이전/다음/오늘)과 날짜 입력칸이 있다.

화면은 위에서부터 세 구역이다.

### 1. 당일 발주 집계 (전체)
- 그날 **모든** 발주 품목(기존 + 가락)을 품목·단위별로 합친 수량.
- 데이터: `getCurrentDispatchGroups` 의 `allItems`(기존 공급처 품목) + `garakItems`(가락 품목)를 합친다.

### 2. 가락 매입 (서울·일산) — 발주 문자 없음
- 서울·일산 식당 주문. 공급처로 문자가 나가지 않는다.
- 품목마다 한 줄: 품목명, 식당명, 수량, 「상차」 또는 「배송」 확인 버튼.
- 확인 규칙은 배치 상태로 정한다:
  - 배치가 배송중(`ordered`) 전이면 **1단계(상차)** 버튼.
  - 배송중 이후면 **2단계(배송)** 버튼.
  - 누르면 `/api/admin/orders/check-items` 에 `{ itemIds: [id], stage }` 를 보낸다. 같은 단계를 다시 누르면 한 단계 뒤로 간다.
- 데이터: `garakItems`의 각 품목에 `check_stage`(0/1/2)와 `batch_status`가 들어 있다.

### 3. 기존 공급처별 발주 내역
- 공급처마다 한 블록. 헤더에 공급처명과 전송 상태.
- 블록 안은 품목 목록(수량·단가)이고, 확인 버튼도 같은 규칙이다.
- 데이터: `getCurrentDispatchGroups` 의 `grouped`(공급처 id → 품목).

## 모바일에서 맞출 것
1. 상단에 날짜 선택(이전/다음 + 날짜 선택)을 두고, 기본 날짜는 웹과 같은 18시 규칙을 쓴다.
2. 탭 또는 구역 3개: 전체 / 가락 / 기존. 웹과 같은 데이터 기준.
3. 가락 탭은 품목별 확인 버튼(상차/배송)을 쓴다. 확인 후 목록을 다시 불러와 서버 값을 맞춘다 — 웹에서 겪은 "다시 열면 안 눌린 것처럼 보임" 문제를 피하기 위함.
4. 기존 탭은 공급처 블록별로 나눈다.
5. 날짜를 바꿀 때마다 해당 날짜 데이터를 새로 받는다.

## API 참고
- 날짜별 발주 데이터는 웹과 같은 서버 로직을 쓴다. 모바일용 엔드포인트가 없으면 `apps/web/lib/dispatch/current-items.ts`의 `getCurrentDispatchGroups`와 같은 조회를 driver API에 추가해야 한다 (`/api/driver/dispatch` 확장 또는 날짜 파라미터 추가).
- 확인 처리: `/api/driver/orders/check-items` 는 이미 있다. 가락 품목도 같은 `order_items.check_stage` 를 쓰므로 그대로 쓸 수 있다.

## 완료 기준
- 날짜를 바꾸면 그날 전체·가락·기존 내역이 웹과 같은 수량으로 보인다.
- 가락 품목을 누르면 상차 → 배송 순서로 확인되고, 다시 열어도 상태가 유지된다.
- 기존 공급처 블록 수량 합계가 웹과 일치한다.
