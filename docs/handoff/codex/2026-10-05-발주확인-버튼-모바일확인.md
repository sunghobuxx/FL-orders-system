# 발주 확인 버튼 — 모바일 앱 확인 요청

상태: 웹 수정 배포 완료(커밋 f464c15). 모바일 앱은 **확인만 요청** — 코드 변경이 필요한지 확인 후 판단.

## 배경
- 웹 관리자 배치 상세(`apps/web/app/admin/orders/[batchId]`)에서 「확인」 버튼을 다시 열면 안 눌린 것처럼 보이던 문제가 있었다.
- 원인: 배치 상세 화면이 품목의 `check_stage`를 가져오지 않아, 화면을 열 때마다 모든 확인이 미확인(0)으로 보였다.
- 수정: `check_stage`를 조회해 넘기고, 체크할 때마다 서버 값을 다시 받아 화면을 맞춘다.

## 모바일 앱에서 확인할 것 (`apps/driver-mobile/app/(tabs)/order/[batchId].tsx`)
1. 상세 응답(`/api/driver/orders/[batchId]`)의 각 품목에 `check_stage`가 실제로 들어오는지 확인.
2. `toggle()`은 체크 후 `load(true)`로 다시 불러온다 — 이미 서버 값을 받으므로 웹과 같은 "안 눌린 것처럼 보임" 문제는 없을 것으로 보인다. 실기기에서 확인 후 이상이 있으면 알려 달라.
3. 확인 단계 규칙은 `apps/driver-mobile/lib/order-check.ts`의 `orderCheckState` / `nextOrderCheckStage` 기준이다. 서버(`lib/orders/check-stage.ts`)와 같은 규칙인지 한 번 대조.
4. 배치가 배송중(ordered)이 되면 두 번째 확인(배송확인, 2단계)이 다시 필요하다 — 버튼이 미확인으로 리셋되는지 확인.

## 모바일에는 해당 없는 변경 (참고)
- 발주 문자 발송 관련 수정(일요일 발송 차단, 제외 품목 원래 수량 재발송 차단, 가락 매입 지역 일산 추가)은 **서버/웹 발송 로직**만 바꿨다. 모바일 앱은 문자를 보내지 않으므로 수정 불필요.
- 이번 수정으로 바뀌는 서버 응답: `check-items` 응답 형식은 그대로. 변경 없음.

## 완료 기준
- 기기에서 품목 확인 → 전부 확인 시 배송중 → 다시 확인 → 배송완료 순서가 끊기지 않고 진행된다.
- 앱을 다시 열어도 확인 상태가 유지된다.
